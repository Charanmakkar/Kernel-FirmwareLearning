# Interview day checklist

Before the interview, confirm its format, duration, time zone, coding environment and permitted tools. Test audio, screen sharing and the editor. Keep the actual JD, truthful resume and a short project index available if allowed. Open no answer banks or AI assistance unless explicitly permitted.

During each task, clarify the contract, state assumptions and explain the invariant before implementing. Test boundary and failure behavior. Pause when evidence contradicts a hypothesis. Distinguish knowledge from inference and describe unfinished work accurately. Ask whether the interviewer wants deeper implementation or a broader tradeoff discussion.

For a project demonstration, have a deterministic command and retained logs ready. Show exactly what ran and state hardware or deployment limits. Prepare one real debugging example and one design you changed after evidence.

Afterward, record uncertain topics and missed cases while they are fresh. Repair them with a concrete exercise. Do not infer guaranteed acceptance or rejection from one question or from conversational tone.
